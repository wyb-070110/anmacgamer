# Contributing to anmacgamer

English · [简体中文](CONTRIBUTING.zh-CN.md)

This guide covers reporting issues, setting up a macOS build environment, running tests, and code conventions.

## Reporting issues

- Search [Issues](https://github.com/wyb-070110/anmacgamer/issues) first.
- Use the bug report template and include the app version, macOS version, chip (Apple silicon or Intel), phone model, Android version, connection type, steps to reproduce, and the archive from **Settings > About > Export diagnostics**.
- Report security issues privately as described in [SECURITY.md](SECURITY.md).

## Submitting changes

1. Fork the repository and branch from `main`.
2. Keep pull requests focused: one change per PR, with tests.
3. Build and run the relevant tests locally; QML lint must have zero warnings.
4. Write English commit messages with a first line up to 72 characters summarizing what changed, followed by a blank line and details when needed.
5. Open a pull request describing what changed and how it was tested.

For large changes (new features, protocol changes, profile format changes), open an issue first.

## Repository layout

| Path | Contents |
|:--|:--|
| `src/` | macOS app in C++20 / Objective-C++20 with Qt 6 / Qt Quick (Metal) and the `gs` CLI (`src/cli`); see [docs/architecture.md](docs/architecture.md) |
| `android/` | Phone side: `protocol`, `server` (plain Java), and `companion` (Kotlin) |
| `protocol/` | Protocol specification (`SPEC.md`) and golden test vectors shared by both sides |
| `sdk/` | Script API types and docs generated by `gs api write`, plus the C header for native extensions |
| `tests/` | Unit, integration, and UI tests, and test data |
| `examples/` | Sample components, tasks, and extensions |
| `tools/` | Build and check scripts (`build_macos_deps.sh`, source rules, frame and touch trace analyzers, generators) |
| `packaging/macos/` | `.dmg` packaging scripts, icon build script, and release notes |
| `third_party/` | Vendored dependencies; see [third_party/README.md](third_party/README.md) |

## Development environment

| Tool | Version |
|:--|:--|
| OS | macOS 14 Sonoma or later (Apple silicon or Intel) |
| Xcode / CLT | Xcode 16+ (Xcode 26+ to recompile `.icon` Liquid Glass assets) |
| Qt | 6.10.3 for macOS (Qt Quick, Qt Quick Controls 2, Qt Shader Tools, Qt Test) |
| CMake & Ninja | CMake 3.28+, Ninja |
| Homebrew libraries | `brew install cmake ninja openssl@3 ffmpeg sdl3 libusb android-platform-tools` |
| Python | 3.10+ |
| JDK & Android SDK (optional) | JDK 17, Android SDK platforms 35 / 36 (only when editing `android/`) |

CMake configure must work offline. Do not add `FetchContent` or other build-time downloads.

## Building on macOS

Qt is discovered at `~/Qt/6.10.3/macos` by default (pass `-DCMAKE_PREFIX_PATH=<path>` otherwise):

```bash
cmake --preset mac-app
cmake --build --preset mac-app
ctest --preset mac-app
```

Presets:

| Preset | Purpose |
|:--|:--|
| `posix-core` | Qt-free core libraries and unit tests (Debug) |
| `posix-core-release` | Optimized core libraries and timing benchmarks |
| `mac-app` | Full local development build (`anmacgamer.app`, `gs`, tests) |
| `mac-release` | Universal (`arm64` + `x86_64`) release build targeting macOS 14+, using LGPL dependencies built by `tools/build_macos_deps.sh` |

Outputs go to `build/<preset>/bin` (`anmacgamer.app`, `gs`, `gs-scripthost`, `gs-exthost`, and test binaries).

## Building the Android side

Set `ANDROID_HOME` to the Android SDK path, then run:

```bash
cd android
./gradlew build
```

This compiles `protocol`, `server`, and `companion`, and runs JUnit tests and lint (lint warnings fail the build). `server` must stay plain Java without Kotlin. Dependency versions live in `android/gradle/libs.versions.toml`.

## Testing

- Module tests use doctest (`gs_base_tests`, `gs_protocol_tests`, `gs_input_tests`, `gs_session_tests`, `gs_media_tests`, `gs_script_tests`, `gs_platform_tests`, `gs_hardware_tests`, `gs_render_tests`, etc.) via `ctest --preset mac-app` (use `-R <regex>` to filter).
- QML lint must report zero warnings: `cmake --build --preset mac-app --target all_qmllint`.
- Protocol tests verify every golden vector in `protocol/vectors/` byte for byte on both C++ and Java.
- Device tests (`gs_adb_device_tests`, `gs_session_device_tests`) run only when `GS_ADB_TEST_SERIAL` is set; otherwise they are skipped.
- Test the mirror window without a phone: `./build/mac-app/bin/anmacgamer.app/Contents/MacOS/anmacgamer --demo-device tests/data/video/emulator_h265.media`. Set `GS_DATA_DIR` to isolate settings during testing.

## Protocol changes

1. Edit `protocol/SPEC.md`.
2. Update `protocol/tools/gen_vectors.py` and run `python3 protocol/tools/gen_vectors.py`.
3. Verify both C++ (`src/protocol`) and Java (`android/protocol`) tests pass.

Do not edit generated vector files by hand.

## Script API changes

After editing `src/script/src/Api.cpp`, run `./build/mac-app/bin/gs api write sdk` from the repository root to regenerate `sdk/`.

## UI strings and translations

- Write UI strings in English in code (`tr()` / `qsTr()`); keep Chinese translations in `src/app/i18n/gamescrcpy_zh_CN.ts`.
- After adding or changing strings, run the translation update target (`anmacgamer_lupdate`) and complete every Chinese entry.
- Built-in help lives in `src/app/help/`: `index.json` defines order, names, icons, and titles; `en/` and `zh_CN/` hold the Markdown articles; register new files in `src/app/CMakeLists.txt`.

## Source rules

`python3 tools/check_source_rules.py` enforces:

- No running or parsing human-readable commands such as `dumpsys` or `wm` in product code (R5).
- No fixed-delay synchronization (`sleep`, delayed single-shot timers, `postDelayed`) (R9). When a delay is the feature itself, annotate the line with `source-rule-allow R9: <reason>`.
- User-facing strings are English in source and have translations.
- Controls under `src/ui/controls` read colors, sizes, and durations only from the theme.
- Every QML `Text` declares `textFormat`.

## Code conventions

- C++20 / Objective-C++20 formatted with `.clang-format` and `.editorconfig`; identifiers and commit messages in English.
- Keep inline comments minimal (a short file header comment is fine; put explanations in PRs or docs). `source-rule-allow` is the only required inline annotation.
- Pull UI colors, type sizes, spacing, radii, and timings from `src/ui/theme`.
- Add tests for new features, and start bug fixes with a failing test.

## Packaging a release

1. Build universal macOS 14+ dependencies (LGPL FFmpeg, dav1d, SDL3, OpenSSL, libusb) with `tools/build_macos_deps.sh`.
2. Build the `mac-release` preset.
3. Run `packaging/macos/package.sh` to bundle Qt frameworks, dylibs, `adb`, and signatures into a `.dmg`.
4. If icon layers under `packaging/macos/icon/` changed, run `packaging/macos/icon/build_icon.sh` (Xcode 26+) to rebuild `Assets.car` and `.icns`.
